| Layer | Choice | Notes |

## Architecture

Single Remix app, no monorepo. Three top-level concerns:

- `app/routes/` — Remix file-based routing. Each route owns its loader, action, and component.
- `app/lib/` — domain modules: `retro/`, `actions/`, `patterns/`, `integrations/`. Business logic lives here, not in routes.
- `app/db/` — Drizzle schema + query helpers. Routes never write SQL inline.

State lives in three places, in order of preference:
1. **The URL** — every retro view, filter, and pane state is reflected in the route or query string. Refresh-safe.
2. **The database** — every action item, vote, and cluster.
3. **Client component state** — only for transient interactions (drag-in-progress, current draft text). Cleared on navigation.

Real-time during the meeting uses LiveKit data-channels. Outside the meeting surface (the writing pre-meeting view, all dashboards), there is no websocket — those views are pure server-rendered.

## Languages & tooling

- TypeScript 5.4, `strict: true`, no `any` without a `// reason:` comment that ESLint enforces.
- pnpm 9 (lockfile committed). Node 20 (`.nvmrc` pinned).
- Biome for lint + format. No Prettier, no ESLint — single tool.
- Vitest for unit + integration. Playwright for the meeting flow E2E.
- Drizzle Kit for migrations. Migrations are forward-only; no `down()`.

## Code conventions

- File names: `kebab-case.ts`. React components: `PascalCase.tsx`. One component per file; default-export the component, named-exports for everything else.
- Folder structure inside `app/lib/<domain>/`: `model.ts` (types), `queries.ts` (DB reads), `commands.ts` (DB writes), `service.ts` (composition). Routes import from `service.ts` only.
- Imports: absolute from `~/` (mapped to `app/`); no deep relative paths (`../../../`).
- Comments earn their place. Document **why**, never **what**. If a comment explains what the code does, rename the code instead.
- Errors propagate. Don't catch in `lib/` unless you're translating an external error into a domain one. Routes catch at the boundary and render an error UI.
- No magic timing. `setTimeout` for race-condition workarounds is a bug; model the state transition explicitly.
- State machines for non-trivial UI flows (the meeting facilitator's state, the writing-phase submission state). XState is allowed; booleans-with-illegal-combinations are not.

## Testing strategy

- **Unit tests**: every `lib/<domain>/service.ts` has tests at the service boundary. Pure functions in `model.ts` get tested when there's logic; types alone don't need tests.
- **Integration tests**: route loaders and actions are tested against a real Postgres (in CI: ephemeral via testcontainers; locally: `pnpm db:test:reset`). No mocking the DB.
- **E2E**: Playwright runs the full meeting flow: schedule retro → write cards → start meeting → cluster → vote → assign actions → end. One happy path, three critical edges (network drop during meeting, owner-leaves, time-up nudge).
- **Accessibility**: every route has a smoke test using `@axe-core/playwright` that fails the build on serious or critical violations. Manual screen-reader passes are required for any change to the meeting surface.
- **No snapshot tests** as primary signal — they're allowed only for stable marketing-page rendering.
- **Coverage**: not tracked as a gate. Behavior coverage > line coverage.

## Deployment & CI

- Branch strategy: trunk-based. `main` deploys to staging on every merge; production deploy is a manual `gh workflow run deploy-prod` from `main`.
- CI: GitHub Actions. Required checks before merge: typecheck, biome, vitest, playwright (smoke subset), `@axe-core` smoke.
- Preview environments: every PR gets a Fly preview app at `pr-<n>.bramble.fly.dev`, torn down on merge.
- Migrations run on deploy, before the new version receives traffic. Forward-only — rollback is a forward migration.

## Performance budgets

Hard limits, treated as build-fails:

- **LCP** ≤ 1.5s on the writing surface (the most visited route). ≤ 2.0s elsewhere.
- **INP** ≤ 200ms across the meeting surface. The vote action specifically: ≤ 80ms perceived.
- **CLS** ≤ 0.05 on every route.
- **Initial JS** ≤ 80kb gzip per route. The meeting surface is the only route allowed to load LiveKit (~30kb) and is budgeted at 110kb.
- **Images**: no decorative imagery on app routes. Marketing routes: AVIF + width-srcset, 80kb max per image, no images above the fold larger than 360kb total.
- **Fonts**: two variable fonts (Inter + Source Serif 4) self-hosted, `font-display: swap`, subset to Latin + Latin-ext.

## Security baselines

- Auth.js sessions, Postgres-backed, 7-day rolling. CSRF baked into Remix actions.
- All env vars via Fly secrets. No `.env` in the repo, ever. `.env.example` only.
- Input validation at every route boundary using Zod. Internal function inputs are trusted.
- CSP: strict, with nonces. No `unsafe-inline`. Inline `<style>` is forbidden.
- Headers: `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` denying camera/microphone/geolocation.
- Dependencies: `pnpm audit` on every CI run; `high` or above blocks merge. Renovate for auto-PRs on patch + minor.
- PII: action-item text and card text are user-generated and may contain PII. Rows are encrypted at rest (Fly Postgres default); no separate field-level encryption for v1.
- No third-party analytics on app routes. Marketing uses Plausible (no cookies).

## Code anti-patterns to avoid

Embedded from `guardrails/code-anti-patterns.md`, plus project-specific bans.

- No premature abstraction — three similar routes is not a pattern; wait for the fourth.
- No half-finished implementations or `TODO: come back to this` branches in `main`.
- No defensive validation on internal function inputs that the type system already guarantees.
- No comments that re-state what the code does. Rename instead.
- No dead code "kept just in case". Version control remembers.
- No backward-compat shims for code we control. Just change the callers.
- No empty catches or catch-and-rethrow-with-worse-message.
- No booleans-as-state-machine. Use a discriminated union or XState.
- No tests that mock everything and assert call shape.
- No snapshot tests as the primary signal of correctness.
- No `utils.ts` / `helpers.ts`. Group by domain.
- No `as any` without a `// reason:` comment.
- No magic timing — `setTimeout` to fix a race is a bug.
- No bypassing safety as a shortcut: `--no-verify`, `--force`, disabled lint rules — the check is usually right.

**Project-specific bans:**
- No animation libraries (Framer Motion, GSAP, Lottie). CSS transitions only. The motion budget in DESIGN.md is small enough that a library is unjustified weight.
- No client-side routing for non-meeting routes. Remix's server-rendering is the default; an `<a>` is a navigation, not a `<Link>` with a SPA loader.
- No GraphQL. Loaders return typed data; we don't need a query language layer.
- No tRPC for now — Remix actions are the RPC.
- No feature flags for shipping incomplete features. If it's not done, it doesn't merge.
