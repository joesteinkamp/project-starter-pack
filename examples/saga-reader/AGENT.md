## Project Summary

Saga is a local-first reading app for long-form nonfiction, built for committed readers who want to *finish* what they start and get value back out of what they highlight. It is a product surface (earned familiarity over novelty): the interface recedes so the text can do the work. The core loop is read → capture in one gesture → return to your marks.

## Workflow Expectations

## Product context

- **Register:** product — a daily reading tool; the chrome disappears into the reading.
- **Primary user:** committed nonfiction readers (15-40 books/year) who outgrew Kindle and read-it-later apps and keep highlights by hand.
- **Jobs-to-be-done:** finish the long thing across devices; capture a passage in one gesture; return to marks and act on them.
- **Personality (three words):** literary, unobtrusive, exacting. Sounds like a well-edited book, never a productivity coach.
- **Top anti-references:** Kindle (closed annotations), Goodreads (reading as performance), Duolingo-style gamification (streaks/badges/confetti).

## UX laws

<!-- Synthesized from DESIGN.md UX foundation. -->

- **Recognition over recall** — always show the exact place ("p.42, *Chapter 3*"); never make the reader remember it.
- **Undo over confirm** — destructive actions show an inline "Undo," never an "Are you sure?" modal.
- **Progressive disclosure** — default surface is just text; notes, tags, export reveal on demand.
- **Keyboard-first power flows** — arrows turn pages, `h` highlights, `/` searches Marks.
- **Empty states are onboarding** — every empty state carries a heading, one sentence, and the primary action inline.
- **Speak the reader's language** — "page," "chapter," "highlight," never "session" or "annotation object."
- **Accessibility is built-in, not cleanup** — WCAG 2.1 AA, reader-controlled type/measure, true low-light dark theme, visible focus, `prefers-reduced-motion` honored.
- **Top flows must stay cheap** — adding a tap to "continue reading" or "capture a highlight," or dropping a highlight anchor on re-import, is a regression regardless of other gains.

## Design laws

<!-- Synthesized from DESIGN.md UI system. -->

- **Color: Restrained** — warm OKLCH paper neutrals + a single terracotta accent on ≤10% of surface. Light default, true-dark companion. No pure black/white. Accent is for marks/active state only, never body copy on a colored field.
- **Typography: editorial serif** — Fraunces display, Spectral body at 18px, 1.25 scale, 1.6 body line-height, measure capped at 68ch (scales with reader's type size).
- **Spacing & layout** — 4px unit (4/8/12/16/24/32/48/64), airy single reading column with edge controls. **No cards in the Reader.** Library books are rows; group with spacing and hairlines, never nested surfaces.
- **Motion: considered** — expo-out, 120/200/320ms; page turns are a quick cross-fade, never a flip. Animate only `transform`/`opacity`; collapse to instant cut under `prefers-reduced-motion`; no delight on the page-turn or save path.
- **Components** — sharp 2px corners (not pill radius), no resting shadows anywhere; surfaces separated by hairlines and whitespace, not elevation.

## Accessibility

- **WCAG 2.1 AA** is the floor, and contrast is measured, not eyeballed — the audit table in `DESIGN.md` lists every meaningful pair; text on an accent fill uses `accentForeground`, control boundaries use `borderStrong` (≥3:1).
- **Keyboard reaches every flow** — arrows turn pages, `h` highlights, `/` searches Marks; every control operable without a pointer.
- **Visible, non-color focus rings** on every control; touch targets ≥ 44×44.
- **`prefers-reduced-motion`** collapses every transition to an instant cut — no exceptions.
- **Reader-controlled type** — size, line-height, and measure are the reader's; the measure cap scales with their setting.
- **Screen-reader labels carry location** — highlights and navigation announce "p.42, *Chapter 3*", not indexes. Copy targets an 8th-grade reading level.

## Code conventions

<!-- Synthesized from CODE.md. -->

- **Stack:** Vite + React 18 (TS) SPA; Fastify (Node/TS) sync+parse API; SQLite/Turso server + IndexedDB client (local-first); Fly.io; magic-link auth; EPUB.js/pdf.js import pipeline.
- **Architecture:** logic on the client, server is sync + parser. Source of truth in IndexedDB, synced to Turso (last-write-wins per field + text-anchor re-match for highlights). State in URL (reading location), Zustand (active session), IndexedDB (persistence). Code grouped by feature.
- **Tooling:** TypeScript strict, pnpm, Biome (lint+format), Vite, Vitest, Playwright.
- **Naming/structure:** kebab-case files, named exports only, feature folders, ordered imports (external → `@/` → relative). No `utils.ts` dumping ground.
- **Comments:** only when the *why* is non-obvious. **Errors:** propagate to the feature boundary and become user-facing messages naming what failed and the next step.
- **Performance (hard limits):** LCP < 2.5s, INP < 200ms, CLS < 0.1; initial route JS < 150KB gzipped; parsers lazy-loaded off the reading path; page turn paints < 100ms; cover images AVIF/WebP ≤ 60KB.
- **Security:** secrets via env; single-use short-lived magic-link tokens; validate at the boundary; uploaded files size/type-checked and parsed with no network access; CSP enforced; Renovate weekly. Treat every imported file as hostile.

## Anti-patterns (always reject)

The following are non-negotiable bans. If the user asks for them anyway, push back once with a concrete alternative; if they insist, comply but flag the trade-off.

### Product

- Vague personas that could describe ten million people.
- Generic positioning that would fit a competitor's site.
- Education framing for an audience that already knows the problem.
- Hedging language ("might", "could", "consider") in brand voice.
- Feature lists standing in for positioning.
- Ornamental metrics ("engagement") instead of real ones.
- Anti-references that aren't real, named things.
- Brand personality of three interchangeable buzzwords.

### UX

- Confirm-instead-of-undo for reversible actions.
- Modal-first thinking where an inline panel/route fits.
- Hidden state (loading/success/error with no acknowledgment).
- Empty states with no guidance or next action.
- Generic error messages that don't say what failed or what to do.
- Inconsistent form validation that dumps all errors at submit.
- Click targets smaller than 44×44 on touch.
- Dark patterns (pre-checked opt-ins, roach-motel cancellation, confirm-shaming).
- Lossy navigation (broken back, refresh wipes state, URL doesn't reflect screen).
- Accessibility treated as end-of-project cleanup.
- Onboarding as a four-step modal tour.
- Forcing recall when the system could offer recognition.

### Design

- Purple gradients on dark as an "AI/tech" default; neon-on-black; pure black/white; >1 accent; gray text on colored fields.
- System-default-only type; body line-height < 1.4; measure > 75ch; type scale < 1.2; gradient text; all-caps headlines > 4 words.
- Nested cards; identical-card feature grids; hero-metric headline; side-stripe borders; default drop shadows; glassmorphism; rounded-rectangle-plus-shadow everywhere.
- Bounce easing; animating layout properties; motion that ignores `prefers-reduced-motion`; delight animations on critical paths.
- Icon-headline-paragraph card grids; three-column "How it works"; 6-logo "trusted by" strips; tilted-screenshot-with-glow heroes.

### Code

- Premature abstraction (wait for the 3rd-4th real use).
- Half-finished stubs / "later" branches.
- Defensive checks on trusted internal code (validate at the boundary instead).
- Comments that restate the code instead of explaining *why*.
- Dead code kept "in case."
- Backward-compat shims for code you own.
- Over-eager error handling (catch-to-rethrow-vaguer, null-for-exception, empty catch).
- State machines modelled as several illegal-combo booleans.
- Test-by-implementation; snapshot tests as the primary signal.
- "Utility" files grouped by part-of-speech.
- Silent type widening (`as any`, bare `@ts-expect-error`, coerced `unknown`).
- Magic timing (`setTimeout` to mask a race).
- Bypassing safety (`--no-verify`, `--force`, disabled lint/type checks).

## AI Slop self-check

Before showing any UI to the user, run this check:

- [ ] Does this look like a stranger could tell an AI made it? If yes, redesign.
- [ ] Are the color choices a category reflex (purple-for-AI, neon-for-crypto, blue-for-banking)? If yes, reconsider.
- [ ] Is every element earning its place, or is there ornament-for-ornament's-sake?
- [ ] Did I default to a hero-metric layout, identical-card grid, or modal-first thinking? If yes, see `DESIGN.md` for the chosen pattern.
- [ ] Does the copy hedge ("might", "could", "consider") instead of taking a stance?

## When to ask the user

- The request contradicts one of the briefs.
- The request requires a decision the briefs don't cover (new section, new flow, new dependency).
- The request would cross a performance / security / accessibility line in `CODE.md` or `DESIGN.md`.
- You are about to take a destructive or hard-to-reverse action.
