## Architecture

Single app, local-first. Business logic lives on the **client**; the server is a sync endpoint plus an import parser. Reading state (position, highlights, notes, tags) is the source of truth in **IndexedDB** and syncs to **Turso** with last-write-wins per field plus a text-anchor re-match for highlights when a book is re-imported. State lives in: the **URL** (current book + location, so refresh/back never lose place), an in-memory store (Zustand) for the active reading session, and IndexedDB for persistence. Code is divided by feature (`library/`, `reader/`, `marks/`, `import/`, `sync/`), not by layer.

## Languages & tooling

TypeScript strict everywhere. pnpm for packages. Biome for lint + format (one tool, fast). Vite for build; Vitest for unit; Playwright for e2e. Node pinned via `.nvmrc`. No Babel — esbuild/Vite only.

## Code conventions

kebab-case file names; named exports (no default exports). Folders grouped by feature, each owning its components, hooks, and store slice. Imports ordered external → internal alias (`@/…`) → relative. Comments only when the *why* is non-obvious (an anchor-matching workaround, a known pdf.js quirk) — never to restate the code. Errors propagate to the feature boundary, where they become user-facing messages that name what failed and what to do next (see the UX error principle). No `utils.ts` dumping ground — helpers live with the feature that uses them.

## Testing strategy

Unit (Vitest) for the import parser, the highlight anchor-matcher, and the sync merge logic — the three places correctness actually bites. e2e (Playwright) for the top three flows: continue reading, capture a highlight, import a book. Behavior, not implementation — no asserting that a function called its mocks; no snapshot tests as a primary signal. No coverage gate, but the anchor-matcher and sync merge must have tests before they ship.

## Deployment & CI

Trunk-based: short-lived branches off `main`, PRs required. GitHub Actions runs Biome, typecheck, Vitest, and Playwright on every PR; all four are required checks. Fly deploys on merge to `main`; PRs get a preview app. Migrations run forward-only.

## Performance budgets

Treated as hard limits. LCP < 2.5s, INP < 200ms, CLS < 0.1. Initial route JS budget < 150KB gzipped; the heavy parsers (EPUB.js, pdf.js) are lazy-loaded only when an import starts, never on the reading path. A page turn must paint in < 100ms. Cover images served as AVIF/WebP, capped at 60KB each.

## Security baselines

Secrets via environment (Fly secrets), never committed. Magic-link tokens are single-use and short-lived. Input validated at the boundary: uploaded files are size-capped and type-checked before parsing; parser runs with no network access. CSP enforced; no inline scripts. Dependencies auto-updated weekly (Renovate) with CI gating the merge. The parser is the largest attack surface — treat every imported file as hostile.

## Code anti-patterns to avoid

- **CODE-01 Premature abstraction** — three similar lines aren't a pattern; wait for the third or fourth real use.
- **CODE-02 Half-finished implementations** — no stubs, no "we'll add it later" branches; ship the feature or don't add the surface.
- **CODE-03 Defensive over trust** — validate at the boundary (imported files, API input), trust internal code; no try/catch "just in case."
- **CODE-04 Comment-as-rename** — if a comment explains *what*, rename the code; comments earn their place explaining *why*.
- **CODE-05 Dead code kept "in case"** — delete unreached branches; version control remembers.
- **CODE-06 Backward-compat shims for code we own** — change the callers instead.
- **CODE-07 Over-eager error handling** — no catch-to-rethrow-vaguer, no `null` where an exception was right, no empty catch.
- **CODE-08 State machines disguised as booleans** — reading/sync state is a machine; model it as one, not five booleans with illegal combos.
- **CODE-09 Test-by-implementation** — test behavior, not the wiring.
- **CODE-10 Snapshot tests as a primary signal** — they detect regressions, they don't define behavior.
- **CODE-11 "Utility files" that grow forever** — group by feature, not part-of-speech.
- **CODE-12 Silent type widening** — no `as any`, no bare `@ts-expect-error`, no coerced `unknown`.
- **CODE-13 Magic timing** — no `setTimeout` to paper over a race; make the dependency explicit.
- **CODE-14 Bypassing safety as a shortcut** — no `--no-verify`, no `--force`, no disabled lint/type checks.
